# 仪表盘首页改版设计

## 1. 背景

当前 `ui-admin/src/views/dashboard/index.vue` 已经具备基础信息展示，但首页仍偏“占位页”形态：

- 首屏层次偏弱，缺少管理后台首页应有的总览感。
- 统计信息只有 2 张卡，信息密度不足，扫读效率一般。
- “常用入口”仍是纵向列表，更像说明清单，不像可操作的首页入口区。
- 欢迎信息、身份信息与系统状态之间缺少清晰分区，页面显得空。

本次改版只调整首页 UI 结构与呈现方式，不扩展新接口、不改变当前数据来源。

## 2. 目标与边界

### 2.1 目标

- 把仪表盘改成更符合管理后台使用习惯的“运营总览式”首页。
- 保持现有数据模型不变，仅通过重新组织页面结构提升信息密度和扫读效率。
- 让首页具备三个清晰区块：核心概览、身份摘要、常用入口。
- 继续复用现有 `page-card` 体系，避免把单页设计做得与整站风格割裂。

### 2.2 本期边界

- 仅修改 `ui-admin/src/views/dashboard/index.vue` 的模板、脚本和样式。
- 仅使用当前 `authStore.profile`、`authStore.menus`、`authStore.permissions` 这组已存在数据。
- 不新增后端接口。
- 不新增全局主题、全局样式变量或额外依赖。

### 2.3 非目标

- 不把首页改造成运行监控大盘。
- 不在本期引入真实待办、公告、告警、工单等新业务模块。
- 不新增复杂图表、轮播或大面积动效。
- 不调整左侧导航、顶部布局或其他页面的视觉方案。

## 3. 方案概览

采用用户已确认的 `B1：均衡总览型` 方案，整体结构为三段式：

1. 顶区：4 张核心概览指标卡。
2. 中区：左侧“当前身份与权限摘要”，右侧“系统提醒 / 能力提示”。
3. 底区：4 张卡片式常用入口。

整体方向为“信息密一点，但仍保持留白和秩序”，重点提升首页的管理总览感，而不是追求炫技型 Hero。

## 4. 页面结构

### 4.1 顶区：核心概览指标

首页顶部放 4 张等宽指标卡，用于建立首屏的扫读节奏。

建议指标如下：

- 菜单总数：`authStore.menus.length`
- 权限点：`authStore.permissions.length`
- 角色数：`authStore.profile?.roleCodes?.length ?? 0`
- 常用入口：`quickEntryCards.length`

说明：

- 前 3 项来自现有数据。
- 第 4 项来自当前页内的快捷入口静态配置，避免引入额外接口或伪造业务数据。
- 每张卡需要同时展示：标题、主值、一句简短辅助说明。

### 4.2 中区左侧：身份与权限摘要

保留“欢迎回来”语义，但不做大 Hero，而是做成更紧凑、更像控制台摘要的信息卡。

该区块包含：

- 页面标题：欢迎回来
- 一句说明文案：概括当前登录身份与控制台能力范围
- 3 个摘要子块：
  - 当前用户
  - 所属部门
  - 角色编码
- 1 条横向补充信息带：展示权限点数量、菜单挂载情况或当前身份标签

数据全部来自：

- `authStore.profile?.nickname`
- `authStore.profile?.deptName`
- `authStore.profile?.roleCodes`
- `authStore.permissions.length`
- `authStore.menus.length`

### 4.3 中区右侧：系统提醒 / 能力提示

该区块不是告警中心，而是首页的次级信息区，用来补足页面右侧信息量，避免版面发空。

建议内容采用静态配置生成，显示 3 条提醒卡片，例如：

- 当前会话已接入菜单与权限能力
- 当前项目前端基于 Vue 3 / Pinia / Arco Design Vue
- 当前首页重点承接系统管理高频入口

设计原则：

- 文字短、可扫读。
- 视觉上弱于左侧身份区与顶区指标卡。
- 保持“提示”定位，不伪装成实时监控数据。

### 4.4 底区：卡片式常用入口

把当前纵向列表改成 4 张入口卡片，分别承接高频系统管理页面。

首批入口保持现有业务含义：

- 用户管理
- 角色管理
- 菜单管理
- 日志管理（落到 `操作日志` 页面）

每张入口卡包含：

- 标题
- 简短描述
- 分类标签
- 小型视觉标识（图标或缩写徽记）
- 关联权限码

交互上支持整卡可点击，目标为已有路由页面；当当前用户缺少对应权限码时，整张入口卡不显示。

## 5. 数据与前端映射

### 5.1 静态配置

页面内部新增轻量级前端配置数组，不抽到全局配置：

- 概览指标配置
- 系统提醒配置
- 快捷入口配置

每项配置只包含当前页渲染所需字段，例如：

- 标题
- 描述
- 标签
- 路由路径
- 视觉 tone / icon 标识

### 5.2 路由映射

快捷入口直接指向现有前端路由：

- `/system/users`
- `/system/roles`
- `/system/access/menus`
- `/system/op-logs`

对应权限码如下：

- 用户管理：`system:user:list`
- 角色管理：`system:role:list`
- 菜单管理：`system:menu:list`
- 日志管理：`system:op-log:query`

如果当前登录用户不具备对应权限，则不渲染该入口卡。

### 5.3 不新增状态管理

本页不新增 Pinia store 字段，不新增请求，不新增缓存层。

## 6. 视觉方向

### 6.1 视觉关键词

- 运营总览式
- 中台首页
- 轻商务感
- 信息密度更高
- 层次分明但不过度装饰

### 6.2 视觉原则

- 延续全局浅色背景与 `page-card` 玻璃感卡片体系。
- 相比当前版本，增加卡片之间的分组感、头尾节奏和辅助层次。
- 少量使用蓝色强调，不把整页做成大面积高饱和蓝。
- 通过卡片排布、局部渐变、图标和标签建立秩序，而不是堆阴影。

### 6.3 响应式要求

- 桌面端优先按三段式结构展示。
- 中等宽度下：
  - 顶区 4 卡自动换行为 2 x 2
  - 中区左右栏上下堆叠
  - 底区快捷入口改为 2 列
- 移动端下：
  - 所有区块单列堆叠
  - 快捷入口改为 1 列
  - 保证摘要信息和标签不挤压换行失控

## 7. 交互与行为

### 7.1 快捷入口

- 整卡 hover 时有轻微抬升和边框强调。
- 点击后使用前端路由跳转。
- 本页不新增显式操作按钮。
- 快捷入口卡需要按权限码做显隐控制，避免用户看到无权进入的入口。

### 7.2 状态展示

- 当 `profile` 缺失时，摘要区使用 `--` 兜底。
- 当 `roleCodes` 为空时，展示 `--`。
- 所有静态提示文案必须可独立阅读，不能依赖未来数据。

### 7.3 动效边界

- 只允许轻量 hover 与卡片过渡。
- 不做大面积首屏动画。
- 不引入复杂时间轴、数字滚动或骨架屏。

## 8. 受影响文件

- `ui-admin/src/views/dashboard/index.vue`

本次默认不改其他文件；如实现时需要补充图标 import、路由跳转或类型声明，应优先控制在当前页面内部。

## 9. 验证方案

### 9.1 必做验证

- 执行 `cd ui-admin && pnpm build`
- 本地打开仪表盘页面，确认桌面端布局与信息层次
- 至少检查一种窄屏场景，确认卡片换行和入口区堆叠正常

### 9.2 验证重点

- 首屏是否比当前页面更有总览感
- 指标区、中区、入口区的层级是否清晰
- 快捷入口是否明显强于原先纵向列表
- 页面是否仍与现有后台整体风格一致

## 10. 风险与控制

- 风险 1：静态提示文案过多，导致首页显得“凑内容”
  - 控制：右侧提醒区只保留 3 条短文案

- 风险 2：信息密度提升后，移动端变拥挤
  - 控制：严格做分段堆叠和列数下降

- 风险 3：首页卡片样式过于突出，和系统其他页不一致
  - 控制：复用 `page-card` 视觉基础，只做局部强化

## 11. 结论

本次改版应被视为“现有首页的结构升级”，而不是重新定义整套后台设计语言。实现时优先保证：

1. 结构更完整；
2. 信息更好扫读；
3. 快捷入口更像入口；
4. 改动范围可控。
