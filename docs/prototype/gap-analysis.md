> 原型：https://ti52kyigh63le.ok.kimi.link （11 屏，材料存于 `docs/prototype/screens/`、`docs/prototype/shots/`）

## 一、已补齐（本次直接实现）

| 原型功能 | 后端现状（改造前） | 决策 | 实现 |
|---|---|---|---|
| 商户工作台 KPI（今日核销笔数/积分、累计核销） | 无统计接口，只有分页记录 | **必要，做** | 新增 `GET /miniapp/merchant/verify/stats`，返回 `{todayCount, todayPoints, totalCount, totalPoints}`（Long） |
| 核销记录按「今天/近7天/近30天」筛选 | records 接口仅分页 | **必要，做** | `GET /miniapp/merchant/verify/records` 增加可选 `days` 参数（1/7/30），默认全部 |
| 券码 QR 展示（券详情、兑换成功弹层） | 后端已返回券码字符串 | **必要，做** | 新增 `components/QrCode.vue`（qrcode-generator + uni canvas，跨端可用） |
| 活动规则页（如何赚分/如何兑换/参与商户说明） | 无内容配置，纯展示页 | **必要，做** | 新增 `pages/activity/rules`，静态内容页，已登记 pages.json |
| 我的页 4 格统计（积分/券/发票/中奖） | 用户信息接口已有积分；券/发票数量前端可数 | **做，但只展示真实数据** | 积分、券、发票三格为真实接口计数；「中奖」格见下方「不做」说明，展示为 0 且不可点 |
| 上传发票页手填商户编号 | 原型无此交互，纯开发期遗留 | **删除** | 上传页移除 merchantId 手填框，发票归属改由后端按发票信息/审核处理 |
| 核销前二次确认（券信息弹层→确认核销） | 接口已支持按码核销 | **做** | 扫码/输码后先展示券信息确认层，避免误核销 |

后端新增/改动文件（共 8 个）：

- `MerchantVerifyStatsResult`（新增 DTO）
- `IipMerchantVerifyMapper.java` / `IipMerchantVerifyMapper.xml`（统计 SQL + days 条件）

接口实测：非商户账号访问 stats 返回「非商户账号或商户未通过审核」✓；将测试会员绑定商户后 stats 返回四个 0 ✓、`records?days=7` 返回 `{total:0, rows:[]}` ✓。

## 二、原型有、后端没有——分析后「不做/暂缓」

| 原型功能 | 分析 | 决策 |
|---|---|---|
| 幸运抽奖九宫格（首页入口 + 抽奖页） | 原型设定「加油支付获得抽奖资格」。这是独立子系统：奖品配置、概率、资格发放与核销、中奖记录、防刷风控、发奖履约，后端零基础。工作量与风险远超本次 UI 对齐目标 | **建议单独立项**。前端暂保留首页入口位但跳转规则页说明，不造假交互 |
| 支付立减（加油支付页） | 需要真实支付通道（微信/支付宝/加油卡）与订单系统，当前后端无支付域 | **不做**，等支付立项 |
| 中奖记录 / 中奖数统计 | 依赖抽奖子系统，无数据源 | **不做**。我的页「中奖」格展示 0，避免编造 |
| 参与商户名单公开接口 | 商户表存在，但公开 C 端名单涉及商户授权与隐私口径 | **暂缓**。规则页以文字兜底说明，后续如需可在 admin 加「是否对外展示」开关 |
| 联系客服 | 无客服渠道配置，不能编造电话/微信 | **不做**，待运营提供渠道后一行配置即可加 |
| 城市切换器 | 业务当前单城运营 | **仅做展示**（首页顶部城市名静态展示，不做切换逻辑） |
| 核销成功率 KPI | 需要新增「核销尝试日志表」记录失败尝试（码错误/已使用/已过期），当前只落成功记录 | **不做**。建议后续加核销尝试日志后再上该指标；工作台第三格用「累计核销」替代 |
| 待结算补贴 KPI | 需要结算子系统（补贴规则、结算单、打款），后端无 | **不做**，同上以「累计核销」替代 |

## 四、已知遗留（如实声明）

1. **完整业务链路未端到端跑通**：兑换→得券码→商户核销→stats 数字变化未联调（测试会员 0 积分，发积分需 admin 审核发票；admin 首登要求改密，未代为操作）。建议人工过一遍：admin 审核一张发票 → C 端兑换券 → B 端扫码核销 → 核对 KPI。
2. **QrCode 组件真机未验**：H5 上因测试会员无券，券详情 QR/兑换成功弹层 QR 未实际渲染过；组件逻辑简单（qrcode-generator 绘 canvas），但微信/支付宝真机端需各验一次。
3. **仅验证了 H5 端**：微信小程序、支付宝小程序端的编译与真机表现未验证。
4. **券列表无门市价字段**：数据库券模板无原价/门市价列，票卡 stub 位置显示「积分兑换」字样；如需展示门市价需加表字段 + admin 表单。
5. **折扣券折扣解析**：折扣从券名正则提取（如「9折」），无结构化折扣字段；券名不含折扣时票卡不显示折扣角标。
6. **文案不一致（轻微）**：首页赞助 chip 为「银行冠名·」，`format.js` 中为「银行赞助·」，未统一。
7. **部署隐患（非本次引入，审计 P0-4 已记）**：`mockLoginEnabled=true`、baseURL 指向 localhost，上线前必须关闭/按环境配置。
